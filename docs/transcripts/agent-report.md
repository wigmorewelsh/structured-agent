Project Overview

The `structured-agent` project is an experiment in structured agents, treating the language model context window as a stack driven by a structured programming language. It aims to allow for efficient context management, simpler implementation of multiple agent patterns, and representation of agentistic loops as recursive function calls. The project is a hybrid Rust and Python system.

## Major Modules

### Core Rust Crates (located in `src/`)

- **`structured-agent`**: This is the main executable crate, serving as the central orchestrator for the agent's operations. It implements the core agent loop, handles tool selection, manages interaction with the environment, and integrates various sub-crates to form the complete agent system.
- **`structured-agent-analysis`**: This crate focuses on static analysis capabilities for the Structured Agent language. It likely performs checks and transformations on the AST to ensure correctness or provide insights, leveraging `codespan-reporting` for diagnostics.
- **`structured-agent-ast`**: Defines the Abstract Syntax Tree (AST) for the Structured Agent language. This is a fundamental component, providing the data structures for representing parsed code, which is then used by the compiler, type checker, and analysis tools. It depends on `structured-agent-runtime` for core runtime types.
- **`structured-agent-bytecode-compiler`**: Responsible for compiling the typed AST into the project's Intermediate Language (IL) bytecode. This crate translates the high-level structured agent code into executable instructions for the Virtual Machine.
- **`structured-agent-gemini`**: Provides integration with the Google Gemini AI model. This crate enables the structured agent to leverage Gemini's capabilities for reasoning and generation, acting as a bridge between the agent's runtime and the external AI service. It depends on `structured-agent-interpreter-runtime` and `structured-agent-runtime`.
- **`structured-agent-il`**: Defines the Intermediate Language (IL) instructions, which are the low-level operations executed by the Virtual Machine. This crate establishes the bytecode specification for the Structured Agent language.
- **`structured-agent-il-analysis`**: Offers analysis capabilities specifically for the Intermediate Language (IL) bytecode. This could involve optimizations, safety checks, or transformations at the bytecode level.
- **`structured-agent-interpreter-runtime`**: Contains core runtime components necessary for executing the IL bytecode in the interpreter. It provides foundational services and types required by the Virtual Machine and other runtime-dependent crates.
- **`structured-agent-macros`**: This is a procedural macro crate, used for compile-time code generation and metaprogramming within the Structured Agent language. It enables developers to extend the language's capabilities through custom syntax extensions.
- **`structured-agent-openai`**: Provides integration with the OpenAI API, allowing the structured agent to interact with various OpenAI models for tasks such as code generation, completion, or chat-based interactions. It depends on `async-openai`.
- **`structured-agent-parser`**: Responsible for parsing Structured Agent language source code. It takes raw text input and converts it into the Abstract Syntax Tree (`structured-agent-ast`) representation, making the code understandable by the rest of the toolchain.
- **`structured-agent-runtime`**: Offers essential runtime utilities and services that are broadly used across the project's various components. It provides common abstractions and helper functions for concurrent operations, data handling, and context management.
- **`structured-agent-stdlib`**: Intended to be the standard library for the Structured Agent language, providing a collection of built-in functions, types, and modules that are commonly used in agent programming.
- **`structured-agent-typecheck`**: Implements the type checker for the Structured Agent language. It ensures type safety and correctness of the code by verifying that expressions conform to their declared types, crucial for the structured nature of the agents. It heavily relies on `salsa` for incremental computation.
- **`structured-agent-typed-ast`**: Defines the Typed Abstract Syntax Tree (TAST), which is an annotated version of the AST where each node carries resolved type information. This is the output of the type-checking phase and the input for the bytecode compiler.
- **`structured-agent-vm`**: Contains the Virtual Machine (VM) implementation, responsible for executing the IL bytecode generated by the compiler. It interprets the IL instructions and manages the execution environment for structured agents.
- **`structured-agent-workspace`**: This crate appears to be a placeholder or utility crate for managing the overall Rust workspace, potentially containing common build configurations or shared resources.
- **`structured-agent-zed`**: Provides language support for the Structured Agent language within the Zed editor. This includes syntax highlighting, bracket matching, code outlining, and auto-indentation, leveraging `tree-sitter-structured-agent` for parsing.

### Supporting Scripts and Tests

- **`scripts/`**: This directory contains utility scripts for development and maintenance tasks.
  - `analyze-clones.mjs`: A Node.js script used to analyze code clones from a `jscpd-report.json`, helping to identify duplicated code sections within the project.
  - `ld-signed.sh`: A shell script (primarily for macOS) that wraps the `cc` compiler, forcing the use of `lld@20` as the linker and then codesigning the resulting binary. This is likely for macOS Gatekeeper compatibility.
  - `sign-rust-toolchain.sh`: A shell script (for macOS) designed to codesign various Rust toolchain binaries, Cargo user binaries, Homebrew-installed development tools (like Node.js, LLVM, Python), and other executables. Its purpose is to prevent macOS Gatekeeper from consuming excessive CPU due to unsigned binaries.

- **`tests/`**: This directory houses the project's test suite.
  - **`tests/fixtures/`**: Contains supporting files or mock servers used by the tests.
    - `mcp_echo_server.py`: A Python script implementing an MCP (Multi-protocol Communication Protocol) echo server using `fastmcp`. This is used as a fixture for integration tests to simulate external tool interactions.
  - **`tests/integration/`**: Contains end-to-end integration tests that verify the overall system's functionality.
    - `pytest.ini`: The configuration file for `pytest`, specifying test paths, file patterns, and general settings for the integration test suite.
    - `test_acp_e2e.py`: End-to-end tests for the Agent Communication Protocol (ACP), verifying the agent's ability to read files, interact with AI models (Gemini), and handle resource links. It includes setup for spawning agent processes and collecting events.
    - `test_acp_server.py`: Integration tests specifically for ACP server event streaming, verifying that events are sent to the ACP client in real-time and not buffered, which is critical for responsive agent behavior.
